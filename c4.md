ENDPOINT
POST /api/enterprise-authentication-service/v2/recovery/initiate (public, no auth)
Request:  { "tenant_id": "nexus", "credential_identifier": "john.doe", "flow_id": "<optional - present = resend>" }
Validate: tenant_id and credential_identifier are required. Trim the identifier. Enforce a sane max length (e.g. 256). A malformed body returns 400.
Response: ALWAYS 202 with the identical shape and message:
  { "flow_id": "<opaque>", "expires_in": <policy.FlowTTLSeconds>, "message": "If the account exists, a verification code has been sent." }
Use policy.FlowTTLSeconds for expires_in on EVERY path (real, decoy, resend, unknown flow) so nothing differs.
The ONLY non-202 responses:
  - tenant unknown OR recovery disabled (policy.Enabled == false or no recovery block) -> 404 {"error_message": "recovery not enabled"} (same body for both cases)
  - throttle exceeded -> 429 (generic body)
  - Redis/store error anywhere -> 503 (fail closed)
  - cooldown / max-resends on resend -> 429 with { "retry_after": n } (see resend)

IdentifierHash = hex(SHA256(tenant + ":" + trimmedIdentifier)). Must be computed exactly as the RecoveryFlow model comment says, because validate uses it as the OTP lockout key. Do not lowercase or alter the identifier unless C0 / the lockout service already normalise it the same way. Check and report.

FLOW A: new initiate (no flow_id)
1. Throttle (C3 rate limiter, policy values):
   - key recovery:rl:id:<IdentifierHash>, limit MaxInitiatePerIdentifier15m, window 15m
   - key recovery:rl:ip:<clientIP>, limit MaxInitiatePerIP15m, window 15m
   Exceeded -> 429. Limiter error -> 503. No PII in keys.
2. FindIdentityByCredentialIdentifier. Each of these becomes a DECOY flow (log INFO with the reason category, do NOT send):
   - ErrIdentityNotFound -> reason "not_present"
   - ErrIdentityAmbiguous -> "ambiguous"
   - state != active -> "disabled" (covers admin deactivation and the 2129 password lockout; see README decision R-D2)
   - traits.auth_provider == "azure_oidc" -> "external_idp"
   Any other error (e.g. Kratos down) -> still a decoy and 202, but log ERROR "recovery_lookup_failed".
3. ResolveRecipients. ErrNoRecipients -> decoy, log WARN "no_recipients".
4. Send OTP: sender := notificationSenders.GetSender(tenant); sender.SendOtp(ctx, recipients, msgs):
   - template = notification.recovery_otp_template_id
   - Values.attributes = notification.attributes resolved from traits, using the same helper login uses
   - If sending fails: keep the flow as a REAL flow (Decoy=false, OTPRefID empty), log ERROR "recovery_otp_send_failed", and still return 202.
5. cache.Create the flow with ttl = FlowTTLSeconds:
   Real: TenantID, IdentityID, IdentifierHash, Decoy=false, OTPRefID, Resends=0, LastSentAt=now, CreatedAt=now.
   Decoy: TenantID, IdentifierHash, Decoy=true, IdentityID and OTPRefID empty, Resends=0, LastSentAt=now, CreatedAt=now.
   Return 202 with the new flow_id.

FLOW B: resend (flow_id present)
1. cache.Get(flow_id). ErrNotFound, OR flow.TenantID != tenant, OR flow.IdentifierHash != computed hash -> return 202 with the same body, echoing the flow_id the caller sent. Send nothing, create nothing. A store error -> 503.
2. Cooldown and max apply to real AND decoy flows identically:
   - now - LastSentAt < ResendCooldownSeconds -> 429 {"retry_after": remainingSeconds}
   - Resends >= MaxResends -> 429
3. Decoy flow -> Resends++, LastSentAt=now, cache.Update, return 202. Send nothing.
4. Real flow: re-check the identity with GetIdentity: it must be active and not azure_oidc. If not (or GetIdentity errors: log ERROR and treat the same) -> convert the flow to a decoy (Decoy=true, clear OTPRefID), Resends++, LastSentAt=now, Update, return 202.
5. ResolveRecipients + SendOtp again -> REPLACE flow.OTPRefID (the previous OTP must stop working), Resends++, LastSentAt=now, cache.Update (it keeps the remaining TTL) -> 202.
   If sending fails: keep the flow, clear OTPRefID, still Resends++ and LastSentAt=now, log ERROR "recovery_otp_send_failed", return 202.

RULES (security review applies)
- Response body, status code and headers must NOT differ between real and decoy paths. No extra headers, no different content-type, no early-return shortcuts that change the response.
- Never log the identifier, recipients, OTP, OTPRefID, flow_id or reset data in clear (A2). Log only tenant, outcome/reason category and the IdentifierHash fingerprint (truncated).
- Audit: "/v2/recovery/" is in the A4 allow-list. Record tenant, IdentifierHash fingerprint and outcome category only. Confirm the request body is excluded from audit logging if the existing audit middleware logs bodies.
- Use RecoveryCache sentinel errors with errors.Is: ErrNotFound vs ErrStoreUnavailable. A store failure is never treated as not-found.
- Do not call Kratos native recovery/verification APIs. No Kratos session or self-service flow.
- Do not change the RecoveryCache interface, RedisStore, or C0/C2.
- Register the route as public and make sure it bypasses auth and any request-decryption config (there is no password in this request).
