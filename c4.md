CONTRACT
Request JSON: { "tenant_id": string, "identifier": string, "flow_id": string (optional, present = resend) }
- Trim identifier. Missing/empty tenant_id or identifier, malformed JSON, or identifier over a sane max length (e.g. 256) -> 400 generic. (This reveals nothing about accounts.)
Success response, ALWAYS 202 for every real and decoy outcome:
  { "flow_id": "<opaque>", "expires_in": <policy.FlowTTLSeconds>, "message": "If the account exists, a verification code has been sent." }
Only exceptions:
  404 {"error_message":"recovery not enabled"} -> tenant unknown, or GetRecoveryPolicy().Enabled == false
  429 -> throttle exceeded, resend cooldown (body includes "retry_after": n seconds), or resends >= MaxResends
  503 -> any recovery-cache or throttle Redis error (errors.Is(err, cache.ErrStoreUnavailable)). Fail closed.
Response body shape, status and headers must be identical for real and decoy paths. expires_in is always policy.FlowTTLSeconds (never a remaining TTL).

FLOW A: NEW INITIATE (no flow_id)
1. Resolve tenant + policy := GetRecoveryPolicy(). Unknown tenant or !Enabled -> 404.
2. identifierHash = hex(sha256(tenant + ":" + trimmedIdentifier)).
3. Throttle (both counters, 15 min window): keys throttle:rec:ip:<clientIP> vs policy.MaxInitiatePerIP15m, and throttle:rec:id:<identifierHash> vs policy.MaxInitiatePerIdentifier15m. Increment, then reject when count > limit -> 429. Redis error -> 503. (AC: the 4th initiate for the same identifier inside 15 min -> 429.)
4. FindIdentityByCredentialIdentifier. Decision table (all decoys: do NOT send, still store a flow and return 202):
   ErrIdentityNotFound           -> decoy, INFO,  category "not_present"
   ErrIdentityAmbiguous          -> decoy, INFO,  "ambiguous"
   state != active               -> decoy, INFO,  "disabled"
   traits.auth_provider == "azure_oidc" -> decoy, INFO, "external_idp"
   any other error (e.g. Kratos down)   -> decoy, ERROR, "recovery_lookup_failed"
   found + active                -> real
5. Real only: ResolveRecipients. ErrNoRecipients -> decoy, WARN, "no_recipients".
6. Real only: sender := notificationSenders.GetSender(tenant); sender.SendOtp with template notification.recovery_otp_template_id and attributes resolved from identity traits exactly as login does. On error: log ERROR "recovery_otp_send_failed", keep the flow as REAL with OTPRefID = "", still 202. On success OTPRefID = returned ref.
7. flow := RecoveryFlow{TenantID, IdentityID (empty for decoys), IdentifierHash, Decoy, OTPRefID, Resends: 0, LastSentAt: now, CreatedAt: now}. flowID, err := recoveryCache.Create(ctx, &flow, FlowTTLSeconds). Return 202 with flowID.

FLOW B: RESEND (flow_id present)
1. recoveryCache.Get(flowID). ErrNotFound, or flow.TenantID != tenant, or flow.IdentifierHash != computed hash -> return 202 with the standard body and a freshly generated random opaque flow_id (crypto/rand, same format as real IDs; do not store it); send nothing, create nothing. ErrStoreUnavailable -> 503.
2. If now - LastSentAt < ResendCooldownSeconds -> 429 with retry_after = remaining seconds. If Resends >= MaxResends -> 429.
3. If flow.Decoy: Resends++, LastSentAt=now, recoveryCache.Update -> 202 (same flow_id returned). Nothing sent.
4. Real: GetIdentity(flow.IdentityID). If not active or azure_oidc -> convert to decoy (Decoy=true, OTPRefID=""), bump counters, Update, INFO "disabled_mid_flow", 202. Lookup error -> same conversion with ERROR "recovery_lookup_failed". 
5. ResolveRecipients again (ErrNoRecipients -> convert to decoy, WARN "no_recipients"). SendOtp again and REPLACE flow.OTPRefID (the previous OTP must stop working). On send failure: ERROR "recovery_otp_send_failed", OTPRefID = "", counters still bumped, 202.
6. Resends++, LastSentAt=now, recoveryCache.Update(flowID, flow) (Update preserves the TTL; ErrNotFound at this point -> treat like a missing flow: 202 with a random flow_id). Return 202 with the same flow_id.
Throttle counters (Flow A step 3) apply to new initiates only. Resends are limited by cooldown and MaxResends.
