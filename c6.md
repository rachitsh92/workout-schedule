CONTRACT
Request: { "tenant_id": string, "reset_token": string, "new_password": string (RSA-encrypted by the UI, decrypted by the middleware before the handler) }
- Malformed JSON or missing/empty tenant_id, reset_token or new_password -> 400 generic. Length caps: tenant_id and reset_token 256; new_password: use a cap that fits the decrypted value (policy max_length) and do not reject an oversized encrypted blob before decryption. Check the middleware.
Success 200: { "status": "password_reset", "sessions_revoked": true|false }
Errors:
  400 { "error_message": "Password does not meet policy", "violations": ["min_length", ...] } -> rule IDs only, never the password or any part of it
  401 { "error_message": "Invalid or expired reset token" } -> every token/tenant/eligibility failure, identical body and headers
  503 -> Redis/cache error, Kratos update failure, identity lookup failure

FLOW (execute in this order)
1. Resolve tenant config and policy := GetRecoveryPolicy(). Unknown tenant or recovery disabled -> 401 (generic).
2. recoveryCache.PeekResetToken(token):
   - cache.ErrNotFound -> 401
   - cache.ErrStoreUnavailable or ANY other error -> 503 (never continue with empty values)
   - returned tenantID != request tenant_id -> 401
   Keep tenantID and identityID from the peek.
3. GetIdentity(tenantID, identityID) once: traits, state. Error -> 503 (log ERROR "recovery_lookup_failed"; the token is NOT consumed). Keep the result and reuse it everywhere below. Do not call GetIdentity again.
4. Password policy validation (BEFORE consuming):
   - min_length 12, max_length 64, at least 3 of 4 classes (lower, upper, digit, symbol); read overrides from credential_policy.password, defaults as stated.
   - Must not contain (case-insensitive: lowercase BOTH sides) any of the identity's identifiers (email, phone, username) or the local part of the email. Skip empty values and local parts shorter than 3 characters, so empty or tiny strings can never cause false violations.
   - Any violation -> 400 with all violations as rule IDs. Do NOT consume the token (the user retries within the TTL).
5. recoveryCache.ConsumeResetToken(token). cache.ErrNotFound -> 401 (a concurrent request won). Any other error -> 503. After this point the token is spent.
6. Eligibility: if state != "active" or isExternalIDP(traits) (azure_oidc) -> 401. Log INFO "disabled_mid_flow".
7. Update via the Admin API: identityService.UpdateIdentityWithPassword(ctx, identityID, tenantID, newPassword, extraTraits):
   - extraTraits: password_last_changed = now (RFC 3339, UTC) and password_expired = false, ONLY for traits that exist in the tenant schema (TraitPolicy.All). A csr-style tenant without these traits sends no extra traits.
   - Error -> 503 (log the error class only; see Open Question 2 about the spent token).
8. If metadata_admin.must_change_password is present: PatchIdentity + PatchIDBuilder replace /metadata_admin/must_change_password false. A failure here is logged ERROR "recovery_patch_failed" and does NOT fail the request (the password is already changed).
9. Clear password lockout: lockoutService.ResetLockoutState(ctx, tenant, identifier, cfg, PASSWORD factor) for EVERY identifier of the identity. Failures are logged as warnings and do not fail the request. This must not abort the loop: try all identifiers.
10. Revoke sessions (Kratos + SMS + Hydra): SessionRevoker.RevokeAll(ctx, tenant, identityID, identifiers, "password_reset"). On failure: ERROR "recovery_revocation_failed" (alertable) and continue with sessions_revoked = false in the response; the status is still 200.
11. Best-effort "password changed" notification: resolve recipients, send with notification.password_changed_template_id. Skip silently if the template id is unset. A failure is logged only. It must never change the response.
12. Audit entry: tenant, outcome category, and the identityID is NOT logged raw. Outcomes: reset_success, reset_success_sessions_not_revoked, invalid_token, tenant_mismatch, policy_violation, ineligible_identity, store_unavailable, update_failed, lookup_failed.
13. Return 200 { "status": "password_reset", "sessions_revoked": <bool> }.

SECURITY RULES
- NEVER log, cache, trace or put into an error message: new_password, reset_token, identityID, identifiers, recipients, or raw error text (%v of an error). Log only tenant, outcome category and the error class. Check that gin binding errors, panic recovery and request/response dump middleware cannot print the body.
- The password variable must not live in a struct that is logged or serialized (no %+v of the request or any struct that contains it).
- Every 401 has an identical body and headers.
- The token is consumed only after policy validation passes and before the Kratos update. Never reorder.
- Use ctx.Request.Context() consistently.
- Add an audit outcome on every exit, including the 400 and 503 exits.
- Do not add decoy logic here: the token is already a proof that OTP validation passed.

TESTS (table-driven with mocks, repo style)
- Happy path: 200, sessions_revoked true; Peek then policy then Consume then Update in that order (assert call order); extra traits sent only when the schema has them; must_change_password patched; ResetLockoutState called for every identifier; RevokeAll called with all identifiers and reason "password_reset"; notification sent.
